# Super_HandAI_z Light — локальные руки для LLM-чата

> **ВНИМАНИЕ — СОВМЕСТИМОСТЬ:** полнофункциональный мост работает только с
> **GLM-5.3-Flash на chat.z.ai** (протестировано). Сам агент универсален:
> работает с ЛЮБЫМ LLM-чатом через копипаст ТЗ. Подробности — в разделе
> «Совместимость» ниже. Не покупайтесь на «любой чат» без прочтения.

Детерминированный агент-исполнитель: LLM-чат придумывает **ТЗ** (план работ в строгом
формате), человек переносит его в локальный агент, агент исполняет шаги в **живом
терминале** Windows (PowerShell 7 / Git Bash через PTY), проверяет результат
(**EXPECT**), пишет файлы, делает git-чекпоинты и возвращает **ОТЧЁТ** обратно в чат.

Человек — супервизор. Мозг — LLM-чат. Руки — локальные и доказуемые.

## Совместимость (прочтите до установки)

| Компонент | Что требуется | Статус |
|---|---|---|
| **Агент** (сервер, UI, терминал, исполнение) | Любой LLM-чат: ТЗ копипастом из любого окна | ✅ универсален |
| **Мост-юзерскрипт** (панель, шаблоны, кнопка «⧉ ТЗ», автолинт) | Только `chat.z.ai` + GLM-5.3-Flash | ⚠ z.ai-specific |
| Системный промпт пака (`glm-system.md`) | Откалиброван под GLM-5.3-Flash | ⚠ под GLM |

**Почему мост привязан:** юзерскрипт зависит от DOM конкретного чата (способ
рендера код-блоков, устройство поля ввода, классы) и от манеры модели выдавать
ТЗ. Мы протестировали это только на связке chat.z.ai + GLM-5.3-Flash.

**Если у вас другой чат/модель:** агент полностью работоспособен — вставляйте ТЗ
в поле вручную (Ctrl+V), отчёты возвращайте в чат копипастом. Мост — ускоритель,
не обязательная часть. Адаптация моста под другие чаты — в roadmap версии Base
(вынесение селекторов в конфиг).

## Философия
- **Проверка = артефакт, не слова.** Каждый шаг обязан иметь EXPECT — машинную проверку.
- **Изоляция.** Всё исполнение — только в `workspace\<задача>\`, выход запрещён.
- **Наблюдаемость.** Полный журнал шагов, честные отчёты с диагностикой отказов.
- **Правила — условия свободы.** Confirm-режим и deny-лист делают автономию безопасной.

## Возможности
- Живой терминал (xterm.js) — команды и вывод в реальном времени
- Формат ТЗ: RUN / RUN_BG (фоновые+WAIT) / WRITE / EXPECT / ASK / GIT commit / NOTE
- Режимы: `auto` и `confirm` (каждый RUN — с подтверждения оператора)
- Отказоустойчивость: `on_fail: stop|continue`, повторные циклы по той же задаче
- Анти-утечка процессов: фоновые гасятся деревом процессов (taskkill /T /F)
- Мост-юзерскрипт (z.ai): шаблоны, кнопка «⧉ ТЗ» с умным линтером
  (сканирует только RUN-скрипты), чтение длинных блоков через CodeMirror state
- Кнопка «⧉ Вставить из буфера» в UI агента
- Витрина «Фичи»: включение/выключение модулей чекбоксами; после манипуляций
  с фичами — Ctrl+R возвращает окна к исходной раскладке
- Кнопка «🧹 Очистить workspace» в мосте — обслуживание в один клик
- Скилл-паки: системные промпты и шаблоны под задачу

## Система фич (v1.1)
Ядро агента больше не меняется функционально — оно предоставляет **слоты**
(beforeRun / afterRun / onFail / routes), в которые загружаются независимые
модули-фичи из `agent\features\*.feature.js`.

**Витрина в UI:** вкладка «Фичи» — таблица модулей (имя, описание, версия,
статус «встроена/после рестарта»), чекбоксы вкл/выкл, загрузка внешних
.feature.js файлов кнопкой «⬆». Состояние сохраняется в `config.json`
(секция `features`); некоторые фичи требуют рестарта (статус «после рестарта»),
подрежимы (например, DRY-RUN тумблер в шапке) переключаются мгновенно.

**Встроенные фичи:**
- `reflect` — счётчик операций; каждые 3 шага печатает чек-лист самонадзора
  (бэкап? EXPECT-проверки актуальны? чекпоинт?)
- `dry-run` — репетиция ТЗ: перехватывает RUN/RUN_BG, печатает «[DRY] было бы:
  <команда>», не исполняя. Тумблер DRY-RUN в шапке UI
- `context-pack` — единый markdown-снимок состояния проекта (git, config,
  последние записи журнала, версии ядра и фич)

⚠ **Фичи исполняются с правами агента** — не устанавливайте код из недоверенных
источников. Формат контракта: `docs\spec\format-spec.md`.

## Base, этап 1: MCP-сервер, hooks-контракты, SKILL-конвертер

### MCP-экспозиция (второй вход того же билда)
- `agent\dist\mcp.js` — MCP-сервер над **stdio** (порт не открывается):
  прямые импорты реестра/журнала/движка — HTTP-сервер 8787 не тронут.
- Шесть инструментов: `run_tz` (асинхронно: сразу `taskId`, вызов не
  держится открытым), `get_status`, `features_list`, `features_toggle`,
  `context_pack`, `purge_workspace` (деструктивный).
- Все вызовы проходят те же guard/AGP/confirm-проверки, что HTTP. Подтверждение
  шага в MCP-сессии = «отмена оператора» → шаг получает SKIP (fail-closed).
- **Единый выделитель задач** (`core/taskHub.ts`): HTTP и MCP не создают двойную
  активность — кросс-процессный lock `data\state\task.lock.json` с heartbeat
  (после crash отпирается по протухшему heartbeat). Реестр задач: `tasks.json`
  — `get_status` видит задачи обоих входов.
- Подключение чат-хоста: `node agent\dist\mcp.js` (нестандартный корень — через
  переменную `SHAI_ROOT`). Версия SDK зафиксирована в `package-lock.json`.

### Hooks-контракты движка (слоты)
- Новый слот **onSessionStart** — активация фич по умолчанию на сессию
  (`ctx.session.flags`), session-состояние живёт ровно одну задачу.
- **additionalContext-канал**: любой хук-слот может вернуть контекст — журнал
  (`FEATURE_CTX`), отчёт (раздел «КОНТЕКСТ ФИЧ»), MCP `get_status`.
- **Never-block контракт**: тайм-бюджет слота + silent fail + самовыход
  (`disableSelf` до конца сессии) — слот никогда не роняет цикл задачи.
- **Внешние хуки** `agent\hooks\*.hook.js`: plain node без exec/&&,
  BOM-strip, CRLF-толерантность, allowlist путей. Контракт —
  `agent\hooks\README.md`.

### SKILL-конвертер (пак ↔ SKILL.md)
- Экспорт: `node agent\dist\skillconv.js export --pack scilss_agent\packs\web-dev --out skills\web-dev`
  — name = id пака, description ≤160, body glm-system.md дословно,
  templates.json — supporting-файлом.
- Импорт: `... import --skill <SKILL.md|каталог> --out <пак>` — body →
  glm-system.md, frontmatter отбрасывается, templates.json — стартовый.
- Sync-guard: `... check ...` и vitest `test\skills-sync.test.ts` — дрейф
  пары `scilss_agent/packs/web-dev ↔ skills/web-dev` роняет сборку тестов.

Заимствованы паттерны/формат (Ponytail v4.9.0, MIT) — атрибуция и границы:
`THIRD-PARTY-NOTICES.md`. Предметный контент донора не переносился.

## Установка и первый запуск (Windows 10/11 x64)
1. Распакуйте архив проекта (например, в `C:\Super_HandAI_z\`)
2. Установите рантаймы по шагам `README-START.md` (прямые ссылки, проверки):
   portable Node 20 в `C:\Utilit\node`, PowerShell 7 и PortableGit в `runtime\`,
   Chrome + Tampermonkey для моста
3. **`setup.ps1`** — мастер настройки: спросит корень, Node, порт и создаст
   `data\state\config.json` под ваши пути
4. **`install.cmd`** — npm-зависимости (интернет)
5. **`run.cmd`** — preflight-проверка окружения → URL агента в Chrome
6. Токен агента **стабильный**: хранится в `data\state\agent.token`, живёт между
   рестартами — мосту вводится один раз
7. ТЗ из `docs\samples\` → ▶ Запустить → отчёт → в чат

Полная инструкция — `README-START.md`.

## Формат ТЗ (кратко)
```tz
# ЗАДАЧ: Название
# META
workdir: new:my-task        # изолированная папка
mode: auto                  # или confirm
on_fail: stop               # или continue
cycle: 1

## ШАГ 1. Смысл шага
RUN shell: pwsh
```pwsh
Write-Output "hello"; exit $LASTEXITCODE
```
EXPECT exit=0
```

Полная спецификация: `docs\spec\format-spec.md`. Эталоны: `docs\samples\`.

## Безопасность — читайте перед использованием
- Агент **исполняет команды на вашей машине**. Контракт строг, но человек в цикле обязателен.
- Deny-лист блокирует заведомо деструктивные операции, workspace изолирует исполнение,
  confirm-режим требует подтверждения каждого шага. **Это снижает, но не устраняет риски.**
- ТЗ приходит из LLM: синтаксис проверяется, но **замысел проверяет человек**. Читайте
  шаги перед запуском. Непонятная команда — Стоп и разбор.
- Не запускайте ТЗ, источник которых вам не доверяете.
- Фичи исполняются с правами агента — устанавливайте только .feature.js из доверенных источников.

## Обслуживание workspace
Временные папки задач — расходный материал: проект завершён → содержимое не нужно
(главное живёт в отчётах и чат-истории).

1. Кнопка **«🧹 Очистить workspace»** в панели моста удаляет **ВСЕ** папки в
   `workspace\`. Необратимо.
2. Перед удалением — **два подтверждения**.
3. При первом использовании мост запросит токен агента — вводится один раз,
   хранится в Tampermonkey. Токен стабильный, между рестартами не меняется.
4. **Защита активной задачи:** при исполнении задачи очистка отклоняется (409).
5. Альтернатива без моста: удалите содержимое `workspace\` вручную.

Очистка — штатная операция: закончили проект → очистили → новый проект с чистого листа.

## Версии продукта
- **Light** (этот репозиторий) — полуавтомат с оператором в цикле: перенос ТЗ и отчётов
  вручную, подтверждения в confirm-режиме.
- **Base** (в разработке) — автомат по максимуму: цикл ТЗ→исполнение→отчёт без ручного
  переноса, оператор — только контрольные точки; мульти-модельность (абстракция моста,
  паки под разные модели); интеграция governance-шлюза (AGP).
- **Pro** (концепт) — Base + роутинг нескольких LLM, межагентское взаимодействие (WCP),
  долговременная память проектов.
